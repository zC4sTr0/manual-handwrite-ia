# EXP-001 — Natural-page transcription with a fixed style reference

**Status:** protocol only; no owner samples, generated pages, or weights are
stored in the repository.

## Purpose

Measure whether the first neural candidate can transcribe a natural page in
the owner's consented handwriting style while preserving text exactly enough
for practical use. This is an owner-only experiment. Do not use another
person's writing, signatures, identity documents, or verification material.

## Hypotheses

- **H1 — content:** a candidate conditioned on five reference samples will
  produce readable target text with lower CER/WER than the v1 `GlyphBank` page
  under the same page layout and scan-effect settings.
- **H2 — style:** blinded owner preference for the neural page will be at least
  as high as v1, without obvious style drift across lines.
- **H3 — limitation:** unseen Portuguese diacritics and punctuation will be
  more error-prone than the characters represented in the reference samples;
  the fallback policy should therefore be measured, not assumed away.
- **H4 — operations:** a local RTX 4070 run can complete a short natural page
  within the verified VRAM budget and without network access after assets are
  installed. This is a hypothesis, not a hardware guarantee.

## Fixed inputs

1. **Reference set:** five owner-consented, non-signature samples from the
   ingestion pipeline, with exact local transcriptions. Keep a second set of
   nineteen samples reserved for the 24-reference ablation; do not tune on it.
2. **Target page:** one A4-equivalent page of 8–12 lines, 500–800 characters,
   written in Portuguese and composed before generation. Include ordinary
   prose plus `ação`, `órgão`, `pão`, `coração`, `ç`, numbers, `R$`, `%`, quotes,
   parentheses, comma, period, colon, and a long compound word. The target text
   must not be copied from any private document.
3. **Baselines:** v1 `GlyphBank` and one neural candidate, initially
   DiffusionPen. Use the same `compose_page` geometry, margins, 300-dpi export,
   seed list, and scan-effect presets.
4. **Seeds:** `0..9` for generation. Do not select a flattering seed for the
   headline result; report all ten and the median.
5. **Candidate configuration:** record repository commit, checkpoint hash,
   model config, sampler, steps, precision, resolution, device, and whether
   fallback was invoked. Use the exact command in the local experiment log.

## Method

1. Verify `owner_consent = true`, reject signature-marked input, and confirm
   that samples/output/model directories are ignored by git.
2. Run a no-network smoke test: load local assets, generate one fixed word,
   and verify that the process makes no outbound request. Abort on OOM or any
   missing-license/weight provenance.
3. Generate ten neural pages and ten v1 pages from the fixed target text.
   Keep intermediate word/line images local and ignored. Apply `limpo` first,
   then apply `scanner-escritorio` and `foto-celular` to paired outputs using
   the same seed. Export PNG/PDF and verify the required
   `generator=manual-handwrite-ia` metadata.
4. Run the fixed local HTR evaluator on the clean and degraded pages. Preserve
   the ground-truth text and machine-readable metrics, but do not put images or
   owner handwriting into git or CI logs.
5. Ask the owner to score anonymized, randomly ordered paired pages. The
   evaluator must not reveal model name or seed. Score legibility, style
   similarity, naturalness, and page-level acceptability on 1–5 scales, plus
   binary failure labels.
6. Repeat only failed cases after diagnosis. Do not silently change text,
   references, sampler, resolution, or scan preset between attempts.

## Metrics

### Automatic

- CER and WER on clean and each scan preset; report each seed and median/p95.
- Diacritic/cedilla exact-match rate on the designated stress tokens.
- Character omission/substitution/insertion counts by token class.
- Margin overflow, clipping, broken-join, and unreadable-line counts.
- Generation seconds per word, page, and end-to-end page; median and p95.
- Peak allocated/reserved VRAM, OOM/crash count, and process exit status.
- Determinism: repeated same seed/config must match a recorded hash or explain
  nondeterministic GPU behavior.
- Network audit result: zero outbound requests during the normal run.

### Human

For each anonymized page: style similarity (1–5), naturalness (1–5),
legibility (1–5), and “would accept this page” (yes/no). Record pairwise
preference neural vs v1. Report the number of raters and missing responses;
with one owner rater, call the result directional rather than statistically
conclusive.

## Decision gates

**Gate A — safety/provenance (mandatory):** owner consent is true; no signatures
are used; all model/checkpoint/dataset licenses are recorded; no network call
occurs; generated exports retain the required metadata. Failure means stop.

**Gate B — runnable:** all ten seeds complete without an unrecovered OOM, with
peak VRAM below the verified local budget and p95 page latency recorded. Failure
means optimize resolution/steps or reject the candidate, not conceal failures.

**Gate C — content floor:** median clean-page CER ≤ 5%, median WER ≤ 10%, and
stress-token exact-match ≥ 90%. These are initial project thresholds, subject
to revision after the first v1 measurement. Failure means retain v1/fallback
and diagnose content conditioning.

**Gate D — perceived quality:** neural wins or ties v1 in owner pairwise
preference and has median style similarity ≥ 4/5, with no more than one
page-level safety/legibility failure in ten seeds. Failure means no v2 default.

**Gate E — regression:** the candidate must not make page layout, clipping,
metadata, or scan-effect gates fail. Failure means keep the neural model behind
an explicit experimental flag.

## Required report

Save a local report outside git containing: date, machine/GPU, software
versions, model/repo/checkpoint identifiers and hashes, license notes, exact
configuration, all seed-level metrics, aggregate metrics, failure examples by
ID (not image), human scores, gate results, and a decision: **promote as
experimental**, **retain behind flag**, or **reject**. A result without a
complete report is inconclusive.

## Expected unknowns before execution

- Actual owner reference count and Portuguese coverage are not yet available.
- The exact HTR evaluator and its Portuguese model are not selected.
- RTX 4070 VRAM, driver, CUDA, and p95 latency must be measured on the target
  machine; they are not inferred from the model README.
- DiffusionPen's custom-data requirements and the redistribution terms for
  IAM-derived assets must be confirmed before any download or fine-tuning.
- The thresholds above are starting gates, not measured baselines.
- If the intended One-DM or paragraph-level model is identified later, it must
  run the same fixed-page protocol before comparison.
